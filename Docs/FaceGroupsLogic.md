# Группы лиц

Экран «Лица и группы» открывается из настроек распознавания лиц выбранной квартиры.
UIKit-координатор передаёт маршрут SwiftUI-экрану через FacesSettingsViewModel
и FacesSettingsStore. Доступность групп, кластеризации и отслеживания определяют
опции оператора. При отключённых группах экран показывает список отдельных лиц.

## Точка подключения

`FaceGroupsStore` не зависит от UIKit, контроллеров, координаторов,
локализованных строк или изображений. Он использует Foundation и RxSwift.

```swift
let repository = ServerFacesRepository(api: apiWrapper, access: accessService, flatId: flatId)
let groups = FaceGroupsStore(repository: repository)
// Сначала подписаться на groups.state и groups.errors, затем загрузить данные.
groups.refresh()
```

Хранить store и подписки на время работы своего экрана. Команды вызывать
на main thread; для тестов можно внедрить другой последовательный scheduler.
`state` сразу отдаёт текущий снимок и последующие изменения.
`currentState` доступен синхронно, `errors` передаёт исходные ошибки без оформления.

Состояние содержит `faces`, `groups`, `filter`, `visibleFaces`,
`selectedGroup`, `isLoading` и `hasLoaded`.

- `select(.all / .ungrouped / .group(id))` — фильтр загруженного списка.
- `createGroup`, `renameGroup`, `editGroup`, `deleteGroup` — управление группами.
- `moveFace`, `detachFace`, `deleteFace` — операции с лицами.
- `cluster(prefix:)` — серверная кластеризация, доступна для непустого списка без группы.
- `toggleTracking` — подписка или отписка от событий группы.

Полный список лиц запрашивается один раз на обновление; переключение фильтра
не делает сетевого запроса. API отдельно поддерживает `getPersonFaces(groupId:)`,
если будущему интерфейсу понадобится серверный фильтр.

Store учитывает возможности оператора, блокирует параллельные изменения,
отменяет устаревшую загрузку и повторно читает данные после успешной или
неоднозначно завершившейся операции. Изменения репозитория и опций обновляют
состояние; собственное уведомление store не запускает повторную загрузку.

Важно: удаление группы удаляет и входящие в неё зарегистрированные лица.
Подтверждение такого действия должен обеспечить будущий UI.
Привязка к другой группе выполняется одним attach-запросом без предварительного detach.
При выключенном отслеживании переименование не меняет существующий watcher.

## Регистрация лица

`apiWrapper.faceRegistrationWorkflow(eventId:flatId:)` создаёт
`FaceRegistrationWorkflow` для одного события.

`save(selection:onRegistered:)` возвращает `Single<APIFaceGroup?>`.
Выбор: `.ungrouped`, `.existing(group)` или `.new(name)`.
Запрос ленивый: без подписки побочных эффектов нет.

Сохранять один экземпляр workflow между попытками:

- Успешная регистрация и создание группы не повторяются при ошибке привязки.
- `isRegistered`, `faceId` и `createdGroup(named:)` показывают подтверждённые шаги.
- `onRegistered` вызывается после регистрации, ещё до назначения группы.
- После неопределённого результата attach выбор «без группы» сначала проверяет
  актуальную привязку на сервере.
- Пустое название, недопустимая группа, выключенная возможность групп
  и параллельное сохранение возвращают типизированный `Failure`.
- Старый сервер может успешно зарегистрировать лицо без возврата ID.
  Повторная регистрация в этом случае не выполняется;
  назначение группы вернёт `.missingFaceIdentifier`.

Workflow не показывает ошибок и не управляет навигацией. Подписчик определяет,
как оформить результат. После регистрации и завершения назначения группы
нужно обновить зависящие данные через `repository.didMutate(sender: workflow)`
(в том числе после ошибки, если часть шагов уже выполнена).

Старый метод `likePersonFace(event:)` сохраняет контракт `Single<Void?>`
для существующего UI. Новый `registerPersonFace(event:)` возвращает ID,
когда сервер его передаёт.

## Проверка без UI и сервера

В Debug можно создать `FaceGroupsStore(repository: MockFacesRepository())`.
Мок хранит записи только в памяти, не использует картинки или UserDefaults,
не посылает уведомления в живую учётную запись. Его кластеризация группирует
идентификаторы фикстур; это не алгоритм распознавания лиц.

Проверки находятся в `FaceGroupsStoreTests`, `FaceGroupsTests`,
`FaceRegistrationWorkflowTests` и `MockFacesRepositoryTests`.
